# 手机内嵌页面备份/恢复真机 E2E 交接

日期：2026-10-14
分支：`feat/storage`

## 目标

补齐手机内嵌页面尚缺的完整真机 UI 验收。USB 页面已经有完整备份/删除/恢复真机报告；该证据不能代替手机页面自己的 UI 流程验收。

## 范围与安全边界

- 使用真实设备页面和移动视口 Chromium/CDP。不得用 USB 服务页、mock API 或 passport-sim 代替。
- 只使用明确指定的专用测试设备和可丢弃的测试 APP/DATA 组。若设备基线中有未获准删除的数据，立即停止；不得删除个人玩法或录音。
- 不移动或硬编码 Flash 地址；不改变固定的 `cardid` / `store` 布局。
- 既有 DATA 原地扩缩容/迁移、断电测试，以及启动结构未变更时的 passport-sim 均不在本期范围。
- 日志不得包含 NVS 原始字节、会话 token、配对码、设备 IP 或串口敏感标识。

## 必须由手机 UI 驱动的流程

1. 记录设备基线：APP/DATA 清单、空闲空间、carve 序号及脱敏后的设备/固件信息。
2. 通过 CDP 使用移动视口打开真实手机内嵌页面，确认页面、控制台和网络请求无异常。
3. 通过手机页面安装一个可丢弃的测试 APP，并在通用容量选择器中选择 DATA 大小。
4. 核对 APP/DATA 使用相同的 `play_id`；通过受支持的测试固件控制通道写入已知测试字节并读回校验。
5. 通过手机页面点击“备份”，使用页面展示的下载链接保存 ZIP。验证 `manifest_version=2`、`complete=true`、恰好一个 APP 组，以及所有载荷的长度和 SHA-256。
6. 通过手机 UI 卸载测试 APP，确认 APP 及其关联 DATA 均已删除，并记录空闲空间和 carve 状态。
7. 通过手机页面选择刚才保存的 ZIP 并执行恢复，确认恢复成功且目的分区为新分配的空间。
8. 使用独立的设备读回路径（适用时可用独立控制的 esptool dump）读取 APP/DATA，逐字节或按 SHA-256 与归档对比。
9. 重启设备，再次打开手机页面，复查所有权和数据摘要。确认目标设备 NVS 未改变；归档 NVS 只校验、不写入。
10. 仅通过手机 UI 删除该测试 APP，确认设备分区几何和空闲空间恢复到基线。

## 验收条件

- 安装、备份、删除和恢复操作均由手机页面 UI 发起。
- 备份失败时不生成不完整 ZIP。
- 恢复只接受完整 v2 单 APP+DATA 归档；格式错误、不完整、所有权不匹配或重复身份必须在修改设备前失败。
- 恢复后的 APP/DATA 字节在重启前后都与归档一致。
- 删除只影响测试 APP 和其关联 DATA，不遗留孤儿 reservation。
- 报告记录 commit SHA、命令/退出码、截图、ZIP/manifest 摘要、前后清单、重启证据和失败原因；不得提交归档文件或 NVS 原始数据。

## 不包含

本交接不要求真实市场录音 UI 测试、既有 DATA 扩缩容、断电测试或模拟器测试。这些事项不得与本期手机页面备份/恢复验收混为一谈。
