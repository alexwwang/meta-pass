# MetaPass v2 存储快照恢复设计

状态：feat/storage 分支实施中；真机验证待完成
日期：2026-10-15

## 1. 目标与非目标

v2 归档定义为设备当前已分配、允许备份的 Flash 分区原始字节快照，不是 APP+DATA 逻辑归档。USB 页面保留历史 v1.1 归档恢复；手机内嵌页面仅接受 v2 快照。两端共享快照 manifest/ZIP 校验和顺序恢复协调器，传输适配器各自使用已有设备接口。

本期不实现事务日志、自动回滚、暂存区、两阶段提交、DATA 扩缩容、独立 DATA 删除或额外修复编排。

## 2. 归档元数据

v2 manifest 包含格式类型/版本、complete 标志、每个目标分区的 label/type/subtype/offset/size、非全 0xFF extent 的文件名/分区相对偏移/长度/SHA-256，以及来源 MetaPass 版本和兼容版本范围。

当前不假设跨版本兼容性：创建时先将兼容范围限定为来源版本本身。版本缺失、无法解析或当前设备版本不在范围内，均在任何 Flash 写入前拒绝恢复，并提示刷回来源 MetaPass 版本后重试。只有存在明确的版本兼容矩阵时，才扩大范围。

## 3. 快照范围与分区安全

1. 通过设备当前分区表解析所有分区；不得使用归档提供的绝对 Flash 地址作为写入地址。
2. 必须从设备运行态（手机 API）或 USB 读取的 ESP app descriptor（项目名 FoloToy-AI-Passport）唯一识别 MetaPass 宿主分区；无法唯一识别时 fail-closed。
3. 排除当前 MetaPass 宿主分区、cardid、只读/受保护分区和未分配 Flash 间隙。
4. 保留当前已分配 NVS 与动态存储分区的原始字节。每个目标分区由 live table 的身份和几何确定；写入适配器只接受分区身份 + 相对偏移。
5. 设备 API 对每次读、擦除、写入重新解析并核对 label/type/subtype/offset/size，拒绝 cardid、当前宿主分区、只读分区和越界请求。

## 4. 恢复步骤

### 阶段 A：只读预检（完成后才允许写）

1. 解析 ZIP 与 manifest，检查格式版本、完整性和 extent 几何。
2. 验证 ZIP 中所有 extent 的字节长度与 SHA-256；拒绝缺失或多余 payload。
3. 获取目标设备实时分区表、当前 MetaPass 版本、运行宿主身份及受保护范围。
4. 检查版本范围；检查快照分区集合与设备所有可恢复分区完全匹配；检查 label/type/subtype/offset/size；检查分区不重叠。
5. 生成恢复计划。任何一步失败，必须零 Flash 写入。

### 阶段 B：按分区顺序恢复

对每个计划分区：
1. 只擦除该 live 分区的完整范围。
2. 按 extent 的分区相对偏移写入原始字节。
3. 从设备独立读回整个分区，以 4096 字节为一块逐字节比对；未包含在 extent 中的稀疏区域预期值为 0xFF。
4. 遇到失败立即停止，不继续后续分区，不声称回滚成功。报告阶段、分区标签、分区相对偏移、预期/实际字节（若可得）及错误原因。

错误分类：
- SNAPSHOT_RESTORE_WRITE_FAILED：分区擦除或写入失败；
- SNAPSHOT_RESTORE_READBACK_FAILED：无法独立读回；
- SNAPSHOT_RESTORE_READBACK_MISMATCH：实际字节与快照不一致；
- SNAPSHOT_RESTORE_BOOT_VALIDATION_FAILED：数据读回已通过，但后续重启/重连验证失败。

对前三类错误，UI 明确标注恢复未完成/不一致，建议刷回 manifest 中的来源 MetaPass 版本，再重新连接和重试。不要夸大为复杂的数据回滚方案，也不要声称失败后设备内容仍保持原样。

### 阶段 C：启动验证

数据读回核验成功只表示存储内容已按快照写入，不等于设备已经成功启动。当前 USB 与手机页面都在数据核验完成后提示用户退出下载模式/重启设备并确认 MetaPass 可重新连接。若未来接入可靠的 reboot/reconnect API，应把启动验证作为独立阶段，不混入数据完整性结论。

## 5. UI 原则

- 在执行任何擦除前展示来源 MetaPass 版本、将覆盖的分区数量，以及“失败时刷回该版本后重试”的明确路径。
- 不使用“自动回滚”“事务安全恢复”等未实现的表述。
- 预检失败：说明未写入 Flash。
- 写入/读回失败：显示“恢复未完成/不一致”、分区标签、相对偏移和来源版本。
- 数据核验通过但未验证启动：明确提示用户手动重启/重连，不显示为启动验证 PASS。
- ZIP 未加密，备份 UI 需提示归档可能含 Wi-Fi 凭证、设备状态和玩法数据。

## 6. 自动化与真机验收

Host tests 覆盖 manifest 来源版本/兼容范围与缺失版本 fail-closed、当前版本不兼容时零写入、分区布局变更/受保护分区不匹配时零写入、按分区擦除与 extent 写入、稀疏 0xFF 区域的全范围读回、读回字节不一致时精确报告分区和相对偏移、写入失败停止后续步骤且不执行回滚，以及数据核验成功与启动验证失败的区分。

真机仍需验证 USB 与手机各自的真实传输层、擦除/写入/读回语义、恢复后的重启与重连。Host mock 不能替代真机证据。
