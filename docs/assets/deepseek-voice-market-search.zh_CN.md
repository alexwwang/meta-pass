## 源码候选为何还不能当作目标固件

FoloToy 的公开仓库 README 将项目描述为小智语音交互入口，可使用 Qwen / DeepSeek 等大模型。源码确实可用于分析其配置、NVS、资源分区和音频流水线；但目前还没有把以下证据闭合：

1. 市场中精确包含“DeepSeek语音”的条目详情 URL / play ID；
2. 该条目实际可安装的固件文件及 SHA-256；
3. 该文件对应的源码版本或构建提交。

因此，现阶段不能把仓库里的 NVS / assets 行为说成“已确认的 DeepSeek语音市场玩法行为”。

## 当前可确认的存储模式（仅限公开源码候选）

公开候选仓库所用的 AI Passport / 小智固件配置与 8 MiB 分区表，指向共享 NVS 和 assets 资源分区；没有发现独立的 FAT 录音档案分区。设置走 NVS 键值 API，资源通过 assets 分区标签读取/映射；语音交互主要走网络音频流水线。由此可提出待验证假设：它更适合作为 NVS / 资源分区对照，而不是独立用户文件 DATA 生命周期的首个验收对象。

这些是源码候选的发现，不是市场条目的最终结论。二进制下载、hash 和构建映射未完成，语音对话是否把任何内容持久化到设备 Flash 也不能仅凭“有语音功能”推断。
