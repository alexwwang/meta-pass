# Release Notes — meta-pass v2.1.0 (2026-10-06)

**TL;DR**: the USB installer's second step is no longer a static three-radio list. It reads the device's live carve record at connect time and shows a **real-time slot table** with one row per slot — offset, size, state, name, and a per-row **Remove** button. You can also **overwrite an existing slot** (with a confirmation dialog) or let the planner auto-allocate a new slot from free space. The LAN phone channel keeps working; the page now surfaces a `MOCK` banner and a persistent MOCK mode so you can walk through all flows in the browser with zero hardware.

---

## What's new

### Dynamic slot management (dynslot)

When you connect a device that carries the dynamic partitioning feature (any image built after the dynslot merge), the installer's **Slot selection** step turns into a live table:

| Column | Meaning |
| --- | --- |
| Slot | numeric index the device reports |
| Offset / Size | exact carve region on the flash |
| State | `valid` (occupied), `invalid` (corrupted record), or `empty` |
| Name | display name written at install time |
| Max image | the most an app image can be to fit here (slot size minus 4 KB tail reserved for the display-name blob) |

A dashed **Auto** row replaces the old "pick slot 0/1/2" radios. It shows the **exact carve geometry** that would be committed if you install right now (`new @offset · size`), or — when the pool has no contiguous gap — the reason why (`needs X, largest gap Y, free Z`) and what to do. Below the table you see a summary line: slot count, occupied slots/bytes, data bytes, free vs total, and the single largest gap.

A language switch re-renders the table live; all new strings are bilingual (EN / zh).

### Safe overwrite and delete

Installing into a slot that already has a sub-firmware is now opt-in: picking an occupied VALID slot triggers a `confirm()` dialog naming slot / offset / size / name, and the install starts only after you click OK. Cancel logs `Install cancelled -- nothing changed` with zero writes.

**Remove** confirms by name/offset/size, erases the slot's first 4 KB (anti-resurrection), commits the carve record without the slot, and re-materializes the 0x8000 partition table on the device. The row disappears immediately; free space updates. Same order and guarantees as the device's `POST /api/install/remove`.

Removing a slot invalidates any explicit radio pick you made earlier (row indices shift after the splice, so a stale index must not retarget another slot).

### Mock mode for browser-only walkthrough

Open the installer URL with `?mock=1` (or `?mock=fresh`, `?mock=legacy`) and the page drives a JavaScript mock device that emulates the real firmware's carve record, slots, prepare/offer/finalize flows, and reboot window. A persistent **MOCK** banner keeps you from forgetting which mode you're in. This lets QA / contributor check-ins be done entirely in-browser — no USB cable needed.

### Phone GET retry absorbs the reboot window

When a device reboots after a remove (or a controlled exit from the store), the LAN page no longer shows a dead-device error. The phone bridge retries GET requests with exponential backoff across the ~20 s reboot window, so a reboot completes transparently from the browser's perspective. `waitDeviceBack` still works and still surfaces a non-recovering device as `status: 0` after the retry budget is exhausted.

## What you should know before upgrading

- **Backward-compatible** with pre-dynslot devices: they still show the legacy fixed-3-slot list. The UI auto-selects slot 0 as default there; overwritten rows stay disabled.
- **No schema change on the device**. The carve record format, the 0x8000 table, and the `cardid` identity partition are byte-identical to v2.0.0.
- **Release artifact is the same single-file layout**: `meta-pass_v2.1.0.bin` flashes at `0x0`. To upgrade, either flash the file at `0x0` (works for a blank/first install) or use the four-region command form to preserve NVS (`bootloader.bin 0x0`, `partition-table.bin 0x8000`, `FoloToy-AI-Passport.bin 0x10000`, `ota_data_initial.bin 0x7fe000`). Upgrading over an existing installation with `write_flash 0x0 meta-pass_v2.1.0.bin` will wipe the NVS WiFi credentials — always prefer the four-region form for upgrades.

## How to build / verify

```bash
./tools/validate.sh --static        # repo checks + host tests (now 235 PASS)
./tools/validate.sh --firmware      # builds the firmware, copies meta-pass_v<version>.bin to build/
node tools/install-slot/test-extract.mjs   # installer unpacking / name-blob tests
python3 tools/realdevice/smoke.py --ip <device>  # optional end-to-end (USB + LAN, unattended)
```

`tools/validate.sh --static` is the gate the CI runs on every push. All host tests — including the new `test-dynslot-record.mjs` (12 PASS) — must stay green before a merge.

---

## What this release does **not** change

- The factory partition layout, `cardid` identity, or bootloader hook contract.
- The LAN store-install flow (pair → offer → confirm → upload → finalize).
- The unsigned-firmware warning page (still warns; the BOOT / CANCEL menu still defaults to CANCEL).
- The marketplace API contract or the Worker proxy rules.
- Support for legacy merged images containing full flash maps — these are still rejected by `verify_firmware.py` at gate time.

If you were tracking the v2.0.0 release notes for the dynslot carve-record format or the bootloader safe-table hook, those are unchanged here; this release adds behavior on top, not on top of those.
