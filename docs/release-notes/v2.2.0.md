# Release Notes — meta-pass v2.2.0 (proposed)

**TL;DR:** Adds whole-device storage snapshot backup and restore for v2 archives, including dynamically allocated child-firmware DATA partitions. Restore validates the archive and target partition layout before erasing flash, preserves the target device's NVS, and is verified to reboot back into a working MetaPass launcher on the tested device.

## What's new

### Whole-device snapshot backup and restore

- Adds a v2 snapshot archive workflow for capturing and restoring eligible allocated storage extents, including child-firmware DATA partitions that are not currently materialized in the runtime partition table.
- The USB service page supports both legacy v1.1 archives and v2 snapshots. The embedded phone page is v2-only and rejects v1.1 archives before device state or flash-write requests.
- USB and phone restore flows share the v2 archive contract and safety rules. Local firmware-file installation remains a USB-page-only feature.
- Archive NVS metadata is validated, but archived NVS is never written to the target device. Existing target-device NVS, including Wi-Fi credentials and local device state, is preserved.
- Before the first erase, restore checks archive integrity and whether the snapshot covers the eligible allocated partitions on the target. A mismatched partition-table shape is rejected before any erase.

### Child-firmware DATA coverage

- Snapshot inventory and device-side read/erase/write operations now resolve carved DATA partitions by their stored identity, including DATA regions absent from the currently materialized partition table.
- This fixes a critical omission where inactive child-firmware DATA could be silently left out of a snapshot.

## Validation

On the dedicated ESP32-C3 AI Passport test device with 8 MiB flash:

- USB v2 snapshot backup passed.
- USB v2 snapshot restore passed; after a manual reboot, MetaPass started and reconnected successfully.
- Embedded phone-page v2 restore passed; after a manual reboot, MetaPass started and reconnected successfully.
- Independent flash dumps matched all **44/44 archived extents byte-for-byte**, including the child DATA extent.
- A target partition-table-shape mismatch was rejected before the first erase.
- USB v1.1 compatibility is covered by host tests. Real-device v1.1 restore was not run because the test device uses dynamic partitioning.

The phone-page backup flow was not revalidated on hardware in this test round. The tested phone restore used the current branch module via local route interception; the deployed CDN module was behind the branch at test time. Confirm deployed-page parity and run the phone backup hardware check before treating the release as fully validated.

## Upgrade and compatibility notes

- **USB service page:** accepts v1.1 legacy archives and v2 snapshots.
- **Embedded phone page:** accepts v2 snapshots only. Use the USB service page to restore a v1.1 archive.
- **NVS:** archived NVS is retained and integrity-checked, but never restored over the target device's NVS.
- **Restore reboot:** successful writes are not considered complete until the device is manually rebooted and MetaPass starts and reconnects.
- **No automatic rollback:** this release does not add transactional restore or automatic rollback. Validate the archive and target layout before restore; a restore failure may require restoring from a known-good archive.
- **Identity and layout:** the cardid location and existing protected partition layout are unchanged.

## Not claimed in this release

- Physical power-loss injection during restore.
- Real-device restore of a v1.1 archive on a legacy fixed-slot device.
- Full byte-for-byte readback of every flash region; comparison covered the 44 archived extents.
- Full source-level unification of the USB and embedded phone pages.
- End-to-end hardware validation of phone-page backup or parity with the currently deployed CDN module.
