# 发布说明 — meta-pass v2.3.0

**一句话：** 把"装得上吗、装成了吗、还连得上吗"三件用户每天都要赌的事变成协议级确定——安装成功确认走"响应体携带终态 + 设备幂等重试"，商店大小显示真实空间占用（app + DATA 预留），token 滑动续约且屏上死码自动自愈。全部来自真机事故定位：截断镜像、槽位消失、假阴性安装失败、过期死码。

## 修复（真机事故驱动）

- **无扩展头 ESP 镜像被解析成截断垃圾（严重）**：固件解析器对"24B 头后是否带 16B 扩展头"的探测此前只看哪条 segment 链能走通，错误布局常给出荒谬小长度（真机：口袋雷达固件被解出 **176B**，真值 2,321,984B）。截断镜像的 SHA 与页侧一致，设备一路放行直到 `esp_ota_end` 才炸 `finalize verify failed`，每次失败回滚 carve，用户重试 4 次后**所有槽位消失**。现改为权威判别：`hash_appended=1` 时对两种布局候选各算 SHA-256 与镜像尾部比对，选中匹配布局，无一匹配即拒绝。真机 + `esptool image_info` 三方验证一致。
- **商店决策页竞态（严重）**：prepare 在 offer_ready → confirmed 之间要跑数百 ms 的 DATA 迁移 + carve 提交 + 分区表重写，250ms UI 轮询极可能把过期决策页顶到屏上且无任何出口，用户按键作用在错误会话状态（真机事故：安装中设备停在过期 CONFIRM/BACK 屏，最终所有槽位消失）。两页均补竞态出口。
- **安装成功但手机误报"安装失败"（假阴性）**：finalize 成功后设备立即离店 → 受控重启 + 作废 token，手机的 done 轮询全程哑火。改为 finalize 响应体直接携带 `{"state":"done","slot":N}`，单请求-响应往返确认成功，不赌任何时序。
- **finalize 响应丢失**：手机按 3s 退避重试至多 3 次；设备对已完成的会话回同形 done JSON（幂等锚点），"已提交但响应丢失"不再被误判成失败。3 次不通则如实报"状态不确定"并引导核对设备。
- **token 固定 30 分钟过期即死**：改为滑动 TTL（每次已鉴权请求顺延）+ P-256 手机硬件绑定；过期后屏上自动补发配对码，页内输码即可续期。401 按原因细分（过期 / 凭证类失败各自独立文案），不再把一切 401 误报成"会话已过期"。
- **QR 页过期死码（本次发布前夜修复）**：QR 页是构建时静态快照，token 30min / 配对码 5min 过期后屏上一直是死码，只能等手机撞 401 被动补发。现 store_tick 周期自愈：token 过期整轮重签；仅配对码过期原地补发（不误伤慢连接手机）；错码次数达上限的死码也自动补发。
- **carve 表重写后 bootloader 按过期映射引导**：装/删触发再物化后，otadata 里旧引导请求的 seq 重映射到已漂移槽位，反复复位循环只能擦 otadata 救回。表重写即刻作废过期引导请求。

## 新增能力

- **商店列表显示真实空间占用**：此前列表只有纯固件下载体积，带 DATA 预留的玩法被严重低估（摩尔斯电码练习器：下载 4.9M，实际共需 7.8M）。worker 把 analyze 的 requiredSize 存入 KV 摘要缓存（键含固件 sha256，固件更新自然失效，不设 TTL），`/api/plays` 逐条富化，冷条目页内后台补算；列表卡片与详情页显示"安装共需（含 DATA 预留）"。too-large 拒绝时也带真实数字与池上限。
- **采集数据上行**：pass-radar 批采集字节经手机页直达采集服务端（`POST /api/capture/ingest`），设备身份由 RCB1 批次头的 cardid 哈希证明，明文不出设备；空间管理面板按需显示上传区（仅已安装拥有 capture 记录的玩法）。

## 刷写方式

`meta-pass_v2.3.0.bin` 为单文件双用格式（bootable body + MPUPV2 尾段）：

- **全新刷机 / 救砖**：在线刷机工具整片写入 → <https://ai-passport.folotoy.cn/tools/web-flasher/>；
- **正常升级（保留槽位与数据）**：设备启动器内 OTA / 商店通道按 MPUPV2 尾段识别升级。

## 验证结果

- 固件 0 error 构建，真机刷写后启动干净（carve 记录、WiFi、商店页正常）。
- 安装链路：真实商店固件（口袋雷达 446 / Radar Hide & Seek 351）走完整 preflight → prepare → 上传 → finalize → done 流程；三种 401 原因逐一真机验证各自文案。
- 截断镜像修复：`esptool image_info` 与解析器三方长度/SHA 一致（176B → 2,321,984B）。
- 列表富化：生产 Pages 实测 0/20 → 12/20 逐轮收敛；摩尔斯电码练习器 1134 列表显示 7.8M。
- 已知非本次引入：CI "Static checks" 两个用例自 2026-10-26 起在干净 HEAD 上同样失败（host 桩与 worker 契约测试），不影响固件产物。
