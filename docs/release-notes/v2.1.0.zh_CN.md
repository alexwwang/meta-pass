# 发布说明 — meta-pass v2.1.0 (2026-10-06)

**一句话**：USB 安装页的"选槽"步骤从静态三个单选变成了一个实时槽位表——连接时读取设备的 carve 记录，按槽位渲染偏移/大小/状态/名字/最大镜像尺寸，每行带删除按钮，支持显式覆盖已占用槽位或让自动规划器从空闲池分配新槽。LAN 手机安装流程不变，页面新增 `MOCK` 浏览器纯前端模拟模式，无需 USB 连线即可完成全部流程走查。

---

## 新增内容

### 动态槽位管理（dynslot）

连接携带动态分区特性的设备时（即安装过 dynslot 版本的任意固件），安装页的**槽位选择**步骤变成一张实时表：

| 列 | 含义 |
| --- | --- |
| Slot | 设备报告的序号 |
| Offset / Size | flash 上的 carve 区域起止 |
| State | `valid`（已占用）、`invalid`（记录损坏）或 `empty`（空闲） |
| Name | 安装时写入的展示名 |
| Max image | 此处能装下的最大 app 镜像尺寸（槽位大小 - 尾部 4 KB 留给展示名 blob） |

原来的"选 0/1/2"被虚线 **Auto** 行替代。点击 Auto 会显示当前会提交的 carve 几何（`new @offset · size`）；若池中没有连续空间则给出原因和应对建议（`needs X, largest gap Y, free Z`）。表格下方有一条摘要：槽数、已占用槽数/字节、数据区字节、空闲 vs 总计、以及最大单条空洞尺寸。

语言切换会即时重绘全表，所有新增文案均为双语文本（EN / zh）。

### 安全覆盖与删除

安装到已有子固件的槽位改为**显式选择**：选中已占用 VALID 槽时弹 `confirm()` 对话框写明槽位/偏移/大小/名字，点击 OK 后才开始烧录；取消则日志输出 `Install cancelled -- nothing changed` 且零写入。

**删除**确认由名字/偏移/大小驱动，先擦被删槽位前 4 KB（防残留复活），提交不含该槽的记录并重新物化 0x8000 分区表，设备立即生效，UI 该行消失、可用空间实时更新。顺序与设备 `POST /api/install/remove` 契约完全一致。

删除操作会作废此前显式选中的槽位（splice 后行下标位移，过期下标不得指向其他槽）。

### MOCK 浏览器模式

在 URL 后追加 `?mock=1`（或 `?mock=fresh` / `?mock=legacy`）即可在纯浏览器里跑通全部流程：JS mock 设备模拟真实固件的 carve 记录、槽位、prepare/offer/finalize 链路与复位窗口。页面顶部有常驻 **MOCK** 横幅，防止误以为是真设备。这个特性让 QA / 贡献者的端到端走查不再需要 USB 连线。

### 复位窗口透明吸收

移除槽位（或退出商店页）后设备会受控重启约 20 秒。phone bridge 对 GET 请求加了退避重试，浏览器侧不再看到"设备离线"报错；`waitDeviceBack` 在重试预算耗尽时仍会返回 `status: 0` 并继续轮询，行为不变。

## 升级须知

- **向后兼容旧版固定三槽设备**：旧设备仍显示静态三单选列表，默认推荐 slot 0，行为与 v2.0.0 一致。
- **设备侧无格式变更**：carve 记录格式、0x8000 物化表、`cardid` 身份分区与 v2.0.0 字节一致。
- **产物仍是单文件布局**：`meta-pass_v2.1.0.bin` 从 `0x0` 烧录。首次刷入可直烧 `0x0`；在已有设备上升级建议用四区域命令，保留 NVS 的 WiFi 凭据：

```bash
python -m esptool --port PORT write_flash \
  0x0 bootloader.bin \
  0x8000 partition-table.bin \
  0x10000 FoloToy-AI-Passport.bin \
  0x7fe000 ota_data_initial.bin
```

用单文件直接 `write_flash 0x0 meta-pass_v2.1.0.bin` 会整扇区擦除，连带 wipe NVS；仅用于全新设备或明确要清盘的场合。

## 构建与验证

```bash
./tools/validate.sh --static        # 仓库门禁 + 主机测试（现为 235 PASS）
./tools/validate.sh --firmware      # 编译固件，产物写到 build/meta-pass_v<version>.bin
node tools/install-slot/test-extract.mjs   # 安装页解包 / 展示名 blob 测试
python3 tools/realdevice/smoke.py --ip <device>  # 可选：真机冒烟（USB + LAN，全自动）
```

`tools/validate.sh --static` 是 CI 门禁，每次推送都跑。新增的 `test-dynslot-record.mjs`（12 PASS）与现有主机测试一起必须保持绿。

## 未变更项

- 出厂分区布局、`cardid` 身份、bootloader hook 契约均未变动。
- LAN 商店安装链（扫码 → 配对 → 提案 → 确认 → 上传 → 终态）不变。
- 未签名固件警告页（BOOT/CANCEL，默认 CANCEL）不变。
- Marketplace API 契约与 Worker 代理规则不变。
- 对全 Flash 合并镜像（含非空用户数据区）的拒绝逻辑不变——`verify_firmware.py` 的门禁照旧。

若你在跟踪 v2.0.0 对 carve 记录格式或 bootloader 安全表 hook 的说明，那些与本次无关；本版本是在上述能力之上增加行为，而非替换底层契约。
