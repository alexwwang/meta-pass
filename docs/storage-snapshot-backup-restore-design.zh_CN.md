# 存储快照式备份与还原设计（2026-10-15）

## 设计决策

v2 备份/还原统一定义为**设备存储快照**，不再是按 APP+DATA 归属关系组织的逻辑归档。目标是在不解析子固件数据格式、NVS key/namespace 或文件系统内部结构的前提下，保留当前设备已分配存储区域中的实际字节。

本决策取代此前“v2 每次只备份一个 APP+DATA 组”以及“还原时保留目标设备 NVS 不变”的方案。NVS 与其他允许分区一样按原始字节整体纳入/恢复，不设计 NVS 专用格式或分支。

## 快照范围

根据连接设备实时读取的分区表，确定允许纳入快照的已分配分区。排除：

1. 当前正在运行的 MetaPass 宿主固件所在分区。
2. `cardid` 分区（设备身份和工厂恢复边界）。
3. 未分配的 Flash 间隙，以及不属于允许分区的区域。

不得硬编码 Flash 地址。宿主固件分区应通过设备报告的当前运行应用/OTA 分区识别；分区表只用作布局描述，不作为快照内容写回。

NVS 在此模型中不再特殊处理：只要它是已分配分区且不属于上述排除项，就纳入快照。因此，还原快照可能把目标设备的宿主 NVS（包括 Wi-Fi 凭证、安装会话 key 等）恢复为备份时的状态。界面必须提示归档可能含有敏感信息，且还原会替换纳入范围的目标存储数据；不能再承诺目标 NVS 保持不变。

## 字节表示与稀疏存储

- 每个纳入快照的分区在 manifest 中记录稳定身份（label、type、subtype）、源 offset、分区大小，以及实际保存的字节 extent 列表。
- 对连续的擦除态 `0xFF` 区域可以采用稀疏编码，但必须记录其位置与长度，以便还原时恢复原始布局。
- 已纳入分区内部的字节不做语义过滤。分区内全 `0xFF` 的范围是可稀疏编码的数据，不等于未分配地址。
- 所有 payload extent 在写入前都必须通过长度和 SHA-256 校验。
- 快照必须完整；读取失败不能静默生成可还原的部分快照。

## 还原规则

1. 解析并校验整个归档：拒绝重复/不安全路径，并在开始写入前验证所有 payload 哈希和范围。
2. 读取目标设备的实时分区表与当前运行的宿主固件分区。
3. 要求归档中的每个目标分区与设备布局兼容。初版可要求分区身份、offset 和 size 完全一致；布局不兼容就拒绝还原，不猜测、不静默重映射。
4. 重新计算目标设备的保护范围；任何归档 extent 若覆盖当前运行的 MetaPass 固件、`cardid`、分区表或未分配 Flash，必须拒绝。
5. 只擦写允许范围内的分区。必要时将稀疏省略的擦除态区域恢复为擦除态；完成后读回并校验。所有分区（包括 NVS）走同一套按分区身份和相对偏移执行的原始字节写入路径。
6. 永不写入当前运行的 MetaPass 固件、`cardid`、分区表或未分配间隙。除非分配器/ carve 元数据本身位于明确纳入快照的分区中，否则不得额外改写这些元数据。

## 版本兼容与页面对齐

- USB 保留历史 v1.1 固定槽归档还原；手机内嵌页只接受 v2 快照。
- 两页共用 v2 manifest、extent 校验、快照采集和顺序恢复协调器。USB 独有本地固件安装入口。
- 旧 APP+DATA 逻辑 v2 归档不能被误识别为快照，必须给出明确拒绝原因。
- manifest 记录来源 MetaPass 版本和包含端点的兼容版本范围。在尚无更宽的兼容矩阵前，范围保守地限定为来源版本本身。目标版本不匹配时，先刷回来源版本再重试。

## 实施状态与下一步

1. **已完成（共享快照基础）：**manifest/extent 校验、ZIP 编解码、payload 长度/SHA-256 校验、擦除态稀疏表示、目标布局预检，以及供两种传输共用的快照采集函数。
2. **已完成（设备 API）：**鉴权的存储清单报告运行中的 MetaPass 版本和宿主身份；分区相对读取、擦除和写入 API 每次都重新核验实时分区身份，并拒绝运行宿主、cardid、只读分区和越界范围。
3. **已完成（USB 传输）：**通过经过校验的 ESP app descriptor 唯一识别 MetaPass 宿主；无法唯一识别时 fail-closed。USB 保留历史 v1.1 归档路径，并在动态布局上支持 v2 原始快照备份/还原。
4. **已完成（手机传输）：**手机 v2 备份和顺序还原使用共享快照采集/恢复核心；手机不增加 v1 归档兼容。
5. **已完成（恢复行为）：**写入前完整预检；逐分区擦除、extent 写入和独立全分区读回（包括稀疏 0xFF 区域）。任何失败立即停止，报告分区和相对偏移。不实现事务日志、自动回滚或复杂修复编排。
6. **仍需完成：**USB 和手机的真机验证，包括还原后字节持久性，以及单独的重启/重连验证。Host mock 与 CI 不能代替真机证据。

## 恢复与 UI 规则

- 写入前展示来源 MetaPass 版本和将覆盖的分区数量。
- 预检失败时明确说明未写入 Flash。
- 擦除/写入/读回失败时说明恢复未完成/不一致，展示分区与相对偏移，并建议刷回来源 MetaPass 版本后重试。
- 数据读回成功不等于启动验证通过。当前两页都要求用户退出下载模式/重启，再确认 MetaPass 可以重新连接。
- 归档未加密，可能包含 Wi-Fi 凭证、设备状态和玩法数据。

## 明确不做

- 不解析或合并 NVS key/namespace。
- 不推断共享 NVS 中各 key 的子固件归属。
- 初版不支持跨分区布局的地址重映射。
- 备份还原不包含既有 DATA 分区扩缩容。
