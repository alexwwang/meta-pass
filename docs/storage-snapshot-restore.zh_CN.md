# 存储快照恢复：设计与测试交接

状态：`feat/storage` 分支实施中。本文描述 v2 快照恢复的目标行为；本文档不代表已经完成真机测试。

## 范围与页面兼容性

- 归档是当前已分配、可纳入快照的存储分区的原始字节快照，包括 NVS 和已分配的存储/DATA 分区。
- 排除正在运行的 MetaPass 主固件分区和 `cardid`。以设备实时分区表为准；不得移动 `cardid`、虚构固定槽位地址，或写入未分配的 Flash 空白区域。
- USB 服务页保留历史 v1 归档恢复路径；v2 快照路径独立处理。手机内嵌页只支持 v2 快照，不增加 v1 归档兼容。
- 本期不调整既有 DATA 分区大小，快照恢复不负责分区扩缩容。

## 归档元数据与兼容性

每个 v2 manifest 记录：

- `meta_pass.system_version`：创建该快照时使用的 MetaPass 精确版本。
- `meta_pass.compatible_versions.min_inclusive` 与 `max_inclusive`：允许读取该归档的 MetaPass 版本闭区间。

来源版本必须位于声明的兼容区间内。由于目前尚无经过验证的兼容矩阵，快照生成时采用保守的精确版本区间（min=max=来源版本），不在没有证据时声称跨版本兼容。后续若要扩大区间，必须有明确且经过测试的兼容策略，不能仅凭归档格式版本号推断。

任何 Flash 写入开始前，恢复流程必须验证归档结构、所有 payload 哈希、目标设备版本、实时分区身份/布局、受保护范围和完整恢复计划。设备版本缺失或无法解析时，必须在写入前拒绝恢复。

## 恢复算法

1. 解析完整归档并验证所有 payload 哈希。
2. 读取设备实时分区清单，并要求 MetaPass 版本有效。
3. 验证归档兼容性，并通过实时分区身份（label/type/subtype 加实时几何信息）解析目标分区。设备适配层根据实时身份解析实际 Flash 操作；恢复协调器只传递分区相对偏移。
4. 按顺序逐分区执行：只擦除该分区、写入归档 extents，然后以 4096 字节分块独立读回整个分区。
5. 读回时，归档未声明的稀疏间隙应为 `0xFF`。逐字节比较，发现第一个不匹配就停止。
6. 任意擦除、写入或读回步骤失败时立即停止。不执行回滚、事务恢复或自动修复。
7. 所有分区均通过读回后，才认为数据恢复已验证。可启动性是独立检查：退出 ROM/下载模式、重启设备，并确认 MetaPass 启动且可重新连接。重启失败不改变已经完成的字节级读回结果。

## 面向用户的失败处理

- **预检失败：** 明确说明尚未开始 Flash 写入，并指出归档、固件版本或实时布局问题。
- **擦除/写入失败：** 明确说明恢复未完成，报告分区和相对偏移，并引导用户刷回归档来源 MetaPass 版本后重试。
- **读回失败：** 明确说明恢复未完成/数据不一致；报告分区、相对偏移，以及可获得的期望字节和实际读回字节；建议刷回来源 MetaPass 版本后重试。
- **读回成功但启动/重连失败：** 明确说明数据读回已通过、但可启动性验证未通过；建议刷回来源 MetaPass 版本。
- 不要夸大可能的数据损失。恢复路径是刷回匹配的 MetaPass 系统版本后重试快照。

USB 页面在 Flash 操作期间通过串口处于 ROM/下载模式，因此当前启动验证是引导式手动步骤：退出下载模式并重启，再确认设备可重新连接。未实际执行重连验证时，不得报告自动验证成功。

## 必需验证项

自动化测试应覆盖：

- 兼容版本接受；不兼容或缺失版本在擦除/写入前拒绝；
- 畸形归档和 payload 哈希错误在写入前拒绝；
- 实时分区身份/布局不匹配，以及主固件/cardid 保护范围；
- 顺序擦除/写入与完整独立读回；
- 稀疏间隙按 `0xFF` 验证；
- 写入和读回失败报告精确的分区相对偏移；
- 首次失败后不继续操作后续分区，不执行回滚；
- 数据验证成功与重启/重连验证失败明确区分；
- USB v1 兼容保持不变，手机内嵌页只接受 v2 快照。

运行 `tools/validate.sh --static` / 仓库 CI 静态检查。真机测试由本地 agent 单独执行；不能把 mock 测试或 GitHub CI 当作真机测试证据。

## 本地 agent 真机测试交接

1. 使用可丢弃测试设备，记录当前 MetaPass 版本和实时分区清单。
2. 使用 USB 页面创建 v2 快照，检查 manifest 版本元数据和 payload 哈希。
3. 确认不兼容/缺失版本的测试归档会在擦除/写入前被拒绝（此项使用 mock/自动化测试，不要伪造真机元数据）。
4. 在兼容的同版本固件上恢复快照。保存页面日志，确认每个目标分区均完成读回验证。
5. 退出下载模式并重启，验证 MetaPass 启动和重新连接。该结果与字节级读回结果分开记录。
6. 不对用户数据执行破坏性故障注入。偏移不匹配、写入失败或重启失败使用自动化 mock，除非已准备专用可丢弃设备和明确的测试镜像。
7. 报告固件版本、设备/分区清单、归档 manifest 元数据、测试步骤、日志、结果和任何不匹配的分区相对偏移。不得移动 `cardid` 或手动替换为绝对 Flash 地址。
